# База знаний по дендрологии — прототип

## Запуск
```
pip install -r requirements.txt
python app.py
```
Открыть в браузере: http://localhost:8000

## Структура базы (две части, сознательно разделены)
1. **species_reference** (data/species_seed.json) — собственный датасет, **209 пород**:
   - 55 видов — куратор-описание вручную (регион, есть высота/долголетие/место обитания/описание)
   - 154 вида — реальный открытый датасет городских деревьев Portland Urban Forestry
     (pdxTrees, github.com/mcconvil/pdxTrees), с латинским названием/семейством/родом.
   Это основа "своей базы данных". Честно: это не 3000, а 209 — дошли до реального предела
   того, что можно было безопасно скачать и проверить инструментами в этой сессии
   (см. ниже "Если нужно больше").
2. **species_cache** — результаты живых HTTP-запросов к GBIF (полная таксономия:
   kingdom/phylum/class/order/family/genus) и Wikipedia (описание/фото), с кэшированием
   на 24 часа. Дополняет и обновляет данные из p.1 свежей информацией из интернета.
3. **species_alias** (data/species_aliases.json) — алиасы бытовых названий
   ("дуб" → "Дуб обыкновенный"), нужны потому что в датасете по 2-4 вида на некоторые рода.

На экране результата поиска оба источника показаны отдельными блоками:
"Наши данные" (из p.1) и "Из сети прямо сейчас" (из p.2) — наглядно для защиты.
Видео — кнопка "Найти видео на YouTube": ведёт на честный поиск по научному названию,
а не на угаданную ссылку (сервис поиска, доступный в этой сессии, не отдаёт реальные
ID видео, поэтому встраивать конкретные "видео" было бы нечестно и ломало бы ссылки).

## Если нужно больше видов (до нескольких тысяч)
GBIF и BGCI GlobalTreeSearch (официальная база ~60 000 видов деревьев, bgci.org)
недоступны для массовой выгрузки из этой среды — доступ к ним заблокирован на уровне
песочницы или защищён от программного перебора. Два рабочих варианта:
1. Скачать CSV с bgci.org/globaltreesearch.php самостоятельно (кнопка на сайте) и прислать
   файл — его можно напрямую импортировать в species_reference тем же скриптом.
2. Через Claude Code (с обычным доступом в интернет) выполнить постраничные запросы к
   https://api.gbif.org/v1/species/search (highertaxonKey=6, rank=SPECIES) и собрать
   нужный объём напрямую.

## Остальные части
- `plots` — участки (УЧАСТОК)
- `trees` — конкретные деревья (участок + порода + возраст/высота/диаметр) — CRUD create
- Автокоррекция — fuzzy-match (rapidfuzz) по названиям из p.1, без ИИ
- "Кости" — бросок 2 кубиков даёт лимит поисков на сессию
- `static/images/` — фон шапки
- Интерфейс: тёмная тема, боковые панели (факты, статистика, быстрый поиск, подсказки),
  подсказки при вводе, кликабельные карточки каталога с окном деталей (без расхода «костей»),
  фильтры каталога, анимации
- Фото в каталоге подтягиваются из Wikipedia автоматически (кэшируются в species_image);
  пока фото нет — иллюстрация по типу дерева. Тип у импортированных видов определён по семейству

## Известные ограничения прототипа
- Лимит поисков общий на приложение (не per-user) — нормально для демо на одной машине
- Если GBIF/Wikipedia недоступны — показываются только "наши данные" (п.1), без падения
- Внешние вызовы не проверялись в среде, где собирался прототип (там нет доступа
  к gbif.org/wikipedia.org) — на обычном интернете должны отрабатывать штатно;
  логика в fetch_gbif / fetch_wikipedia в app.py

## Расширение датасета
Чтобы добавить виды — правьте data/species_seed.json (и, если нужно, data/species_aliases.json),
удалите dendro.db и перезапустите: таблицы пересоздадутся и заполнятся из JSON заново
(если species_reference не пуст — повторная загрузка не произойдёт, это защита от дублей).


## Версия 2: что изменилось и зачем
**Почему не было фото из Википедии.** Wikimedia может отклонять запросы с безымянным User-Agent
(HTTP 403), а `python-requests` так и представляется. Теперь все запросы идут с понятным
User-Agent (`DendroKB/1.0 ...`). Причину любого сбоя видно в панели «Источники данных»
(справа) и в строке «Источники» под результатом поиска — код ответа не прячется.

**Цепочка фото:** Wikipedia → iNaturalist → GBIF. У каждого фото показаны источник, автор и лицензия.

**Слои системы (что объяснять преподавателю):**
1. Хранение знаний — признаки вида (тип, листва, форма листа, плод, отношение к свету, место,
   высота), таксономия, алиасы, связи «родственные виды» (один род / одно семейство).
2. Обработка знаний — автокоррекция (rapidfuzz) и определитель по признакам: взвешенное
   сопоставление, результат объясняется (что совпало, что нет, что неизвестно). Без ИИ и без сети.
3. Живые источники — GBIF, Wikipedia, iNaturalist; кэш; проверка состояния источников.
4. Пополнение знаний — «Добавить породу», «Сохранить в базу знаний» (найденное вживую становится
   записью собственной базы), добавление деревьев и участков.

**Важно про данные.** Признаки определителя (форма листа, плод, свет, место обитания) заполнены
для 55 курируемых видов на основе общих ботанических знаний — сверьте их со справочником
(например, Деревья и кустарники СССР / Флора Беларуси) до защиты. У 154 импортированных видов
таких признаков нет, в определитель они не входят.

Старые базы dendro.db обновляются автоматически (добавляются недостающие столбцы).


## Версия 3: видео внутри сайта и «кости» со скрытыми статьями

**Видео.** Кнопка «▶ Видео» открывает поверх страницы список (миниатюра, название, канал, дата,
длительность, метка RU/EN); клик по строке запускает видео в плеере на сайте (встраивание
youtube-nocookie.com). Список складывается из двух частей:
1. *Автоматический поиск* — официальный YouTube Data API v3 (русский и английский запрос,
   результат кэшируется на неделю). Нужен бесплатный ключ: Google Cloud Console → проект →
   включить «YouTube Data API v3» → «Credentials» → «API key». Ключ положить в файл
   `youtube_api_key.txt` рядом с `app.py` (или в переменную окружения `YOUTUBE_API_KEY`) и
   перезапустить. Квота: 10 000 единиц в день, один поиск ≈ 200 единиц (два языка), кэш экономит.
2. *Своя база видео* — «Вставьте ссылку на видео»: название и канал подтягиваются через
   официальный oEmbed без ключа, видео сохраняется в таблице `species_video` и показывается
   всегда. Без ключа работает только эта часть.
Состояние ключа видно в панели «Источники данных».

**Кости.** Один бросок за сессию (сессия = cookie браузера; кнопка «Начать новую сессию»
под костями нужна для показа). Сумма кубиков = число живых поисков = номер скрытой статьи.
12 скрытых статей (`data/hidden_articles.json`): №2–12 по сумме и одна бонусная за дубль.
Сервер отдаёт статью только той сессии, которая бросила кости.
Тексты статей написаны ИИ и содержат поле «Как проверить» — перед защитой сверьте факты
и учтите их в доле ИИ-контента (не более 30 %) с пометкой по образцу кафедры.


## Версия 4 (после ваших правок)
- **Видео без ключей Google.** Список строится пакетом `youtube-search-python` (неофициальный парсер выдачи
  YouTube); если пакета нет, сайт работает, а в списке видео остаются только добавленные вручную. Ключ API
  и Google Cloud не нужны. Парсер может перестать работать при изменениях YouTube — тогда помогает
  `pip install -U youtube-search-python` или добавление видео по ссылке.
- **Даты видео.** Парсер отдаёт «3 years ago» — на сайте это показывается как «3 года назад».
- **Фото.** Размер миниатюры Wikipedia 320px (640px сервер отклоняет). После смены логики очистите кэш
  (`clear.py`: таблицы `species_cache` и `species_image`).
- **Дубль в костях не повторяет информацию.** Бонусных статей теперь шесть. Выбор идёт по значению кубика,
  но уже показанные этому браузеру пропускаются; круг из шести статей проходится без повторов, затем
  начинается заново. Что видел браузер, хранится в таблице `seen_bonus` (cookie `dendro_uid`, год).
  Основные статьи (сумма 2–12) по-прежнему привязаны к сумме кубиков.


## Версия 5: свежие данные отовсюду и исправления автокоррекции
**Свежее в сети.** Кнопка «🌐 Свежее в сети» в карточке породы (рядом с «▶ Видео») открывает окно с вкладками
Видео / Статьи / Новости / Наука / Соцсети. Модуль `fresh.py` параллельно опрашивает 12 источников и сортирует результат по
дате (новое сверху): YouTube (как раньше), RuTube, Dailymotion, PeerTube (sepiasearch.org), Wikimedia Commons,
Internet Archive, Wikipedia (ru и en), Google News (ru и en, RSS), OpenAlex (научные публикации), Reddit.
Результат кэшируется на час (кнопка «Обновить» сбрасывает кэш). Статус каждого источника виден под списком.
Маршрут: `GET /api/fresh?subject=...&name=...`.

**TikTok и Instagram.** Открытого API поиска у них нет, а парсинг их выдачи запрещён правилами площадок и ненадёжен.
Поэтому: (1) показываются ссылки на их страницы поиска по породе (также Pinterest, X, VK, Facebook); (2) любой найденный
ролик/пост добавляется в базу по ссылке (`POST /api/links`, таблица `species_link`); название и миниатюра подтягиваются
через публичный oEmbed для TikTok, Vimeo и YouTube (для Instagram oEmbed требует токен — сохраняется ссылка).

**Автокоррекция.** Исправлены два дефекта из тестирования: `lipa` теперь даёт «Липа мелколистная» (транслитерация),
`дyб` с латинской y — «Дуб обыкновенный» (замена латинских двойников кириллицы). Запрос латиницей сначала сверяется с
латинскими названиями, потом транслитерируется, и только затем идёт нечёткий поиск (пороги 80 и 85).

**Важно.** Новые коннекторы написаны по документации API и проверены на заглушках ответов; живые запросы в среде сборки не
выполнялись (нет доступа в интернет). Если какой-то источник вернёт ошибку, причина видна в «Состояние источников».


**Отбор по теме и по дате (версия 5.1).** Раньше источники искали по отдельным словам и выдавали посторонние ролики
(например, по «акация белая» находились сериалы). Теперь: (1) запросы идут точной фразой («Акация белая», «Robinia
pseudoacacia»); (2) каждый найденный материал проверяется по заголовку и описанию — в нём должно быть латинское название,
или русское название целиком (в любом порядке слов и с любыми окончаниями), или название породы вместе со словом о
деревьях (дерево, лес, сад, посадка, tree, forest …); «Дубай» и «дубовый паркет» отсеиваются; (3) отбрасывается всё, что
старше 2 лет (`MAX_AGE_DAYS = 730` в `fresh.py`) или без даты публикации; (4) дубликаты убираются. Для источников, которые
умеют, дата отсечения передаётся и в сам запрос (Dailymotion, PeerTube, OpenAlex, Internet Archive, Google News).
